# 10. v0.3.1: profile form, idle module and open gaps

Status: draft for owner review, 2026-11-19. Builds on `09-game-profiles` and v0.3.0 (commit f69eb63). Server release v0.3.1 and SDK release `unity-v0.2.1`. Every change is an addition, so games on SDK 0.1.x or 0.2.0 need no update.

## 1. Profile form

The owner found the raw JSON box in Settings hard to use. A form replaces it, and the JSON box stays only under an "Advanced" toggle.

- **Preset.** A dropdown. Choosing a preset fills the fields below, and the detected preset is marked "Detected".
- **Play label.** A text field, for example Level, Match or Run.
- **Tracks.** One row per track: a checkbox, the key, a label, the milestones as comma-separated numbers, and a scale of linear or log10 (section 2.1). Suggested rows come from the `props.track` values seen in the last 7 days.
- **Dimensions.** One row per props key seen on play events in the last 7 days: a checkbox, a label, a multi-value checkbox, and the number of distinct values seen. At most 12 dimensions can be checked.
- **Flows.** One checkbox per flow seen in the last 7 days.
- **Saving.** Saving rebuilds the rollups, as today. The form shows "Rebuilding" until the cron finishes.

Reads for the form come from the rollups and a bounded raw sample of the last 7 days, at most 2,000 rows, so the Settings page stays near today's cost.

## 2. Idle and tycoon module

Idle and tycoon games have no levels or matches. They play on while the app is closed, reset progress for a permanent bonus (prestige), and their numbers grow from 1e3 to 1e30 and beyond.

| Concept | In an idle game |
|---|---|
| Play | `kind: run` is one prestige cycle. `play_end` has `result: prestige`, `value` = the prestige currency gained, and `duration_ms` = the time to prestige |
| Tracks | `stage`, `prestige_count`, `income_per_sec` (log10), `account_level` |
| Dimensions | `building`, `upgrade`, `boost`, `offer` |
| Flows | FTUE: first building, first upgrade, first prestige |

The `idle_tycoon` preset in `09-game-profiles` section 3.1 changes from play kind `session` to `run`, with these tracks and dimensions. `prestige` is added to the allowed `play_end` results; it counts as a completed run, not as a win.

### 2.1 Log scale tracks

A track may set `"scale": "log10"`. Its buckets are then powers of ten (1e3, 1e6, 1e9 and so on), and milestones are written as numbers such as `1e6`. This also suits RPG power scores and damage.

### 2.2 Session rhythm

- **SDK.** `session_start` gets `props.since_last_ms`, the time since the previous session ended on this device. The first session has none.
- **Rollup.** Gaps are counted in the buckets under 1 hour, 1 to 4 hours, 4 to 12 hours, 12 to 24 hours and over 24 hours, per day, version and platform.
- **Dashboard.** The Overview shows sessions per player per day and the gap histogram for every project, not only idle games.

### 2.3 Offline rewards

A new standard event:

| Event | Fields |
|---|---|
| `offline_reward` | `duration_ms` (time offline), `value`, `currency`, `props.multiplier` (1, 2, 3), `props.via` (`free`, `ad`, `iap`) |

The Economy page shows the average time offline, the share of offline rewards taken with an ad multiplier, and the offline share of all currency earned.

### 2.4 Large numbers

The dashboard formats large values with suffixes (K, M, B, T, Qa, Qi and so on, then scientific notation past 1e33), and economy charts get a log axis toggle. The `value` column is REAL and holds up to about 1e308, so the schema does not change.

### 2.5 Event budget for idle games

The preset documentation tells the game:

- Send `progress` on milestones, at session start and at prestige, never on every value change.
- Summarize upgrade purchases per session in `session_end` props, for example `upgrades_bought`, instead of one event per purchase.
- Aim for fewer than 15 events per session.

## 3. Open gaps from v0.3.0

| Gap | Fix |
|---|---|
| Profile detection reads only the first batch, not the last 7 days | Detect from the last 7 days of `event_days`, rerun daily until the owner saves a profile |
| `tutorial_skip` is not mapped | Count it as a skip at its step in the flow `tutorial` |
| A play event without `level` is ignored | Store it under the play key `(none)` so totals stay complete |
| The players column is not filtered by kind | Count players per kind |
| Settings reads 479 rows | Keep it under 150 once the form ships (section 1) |

## 4. SDK `unity-v0.2.1`

- `Idolytics.OfflineReward(durationMs, value, currency, multiplier, via)`.
- `since_last_ms` on `session_start`, computed from the last session end saved in PlayerPrefs.
- `PlayResult.Prestige`.
- Additions only; the 0.2.0 API and the wire format stay.

## 5. Done when

- The form saves the same profile as the JSON it replaces, and a test round trips every preset.
- Idle shaped data on smoke-test matches a hand count. Use 3 prestige runs, log10 income milestones, offline rewards with and without ads, and session gaps in at least 3 buckets.
- Ninja Smash and match shaped numbers are unchanged from v0.3.0.
- The EditMode tests pass in `sdk/unity-host`, including `since_last_ms` across a simulated restart.
